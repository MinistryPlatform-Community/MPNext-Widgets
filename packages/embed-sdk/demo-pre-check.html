Pre Check-In

Check your household in for a day's check-in events before you arrive.

<next-pre-check>
Why this demo pins a date. The widget defaults to today in the MP domain's time zone, and the reference instance has no check-in events today — so without event-date every day of the year shows the (correct) empty state, which reads like a broken widget.
2018-06-12 is the one date on the sample domain where household 5 (the Check-me-in family) actually resolves rows: event 2 Sample Check-in1 has Search_Results = 1 (Allow Guests), so every household member is listed. The 2025 Sunday/Tuesday classes are Search_Results = 3 (Show Expected Only) and their groups do not overlap this household's, so MP correctly shows nobody for them — a useful second case to try.

Widget CodeAdd this to any page where you want this widget

<!-- Defaults to today in the MP domain's time zone, resolved on the
     server. This is what a church puts on its page. -->
<next-pre-check></next-pre-check>

<!-- Pin a specific day (wall-clock YYYY-MM-DD, the church's calendar) -->
<next-pre-check event-date="2018-06-12"></next-pre-check>

<!-- Let the visitor move between days without a new URL -->
<next-pre-check allow-date-picker="true"></next-pre-check>

<!-- Opt back into legacy's ?eventDate= host-page query parameter.
     Off by default: silently obeying an arbitrary URL parameter is a
     surprise on a shared CMS page. -->
<next-pre-check read-query-string="true"></next-pre-check>

<!-- Listen to events -->
<script>
  const widget = document.querySelector("next-pre-check");
  widget.addEventListener("preCheckLoaded", (e) => {
    console.log("Pre check-in loaded:", e.detail);
  });
  widget.addEventListener("preCheckSaved", (e) => {
    console.log("Pre check-in saved:", e.detail);
  });
  widget.addEventListener("preCheckError", (e) => {
    console.error("Pre check-in error:", e.detail);
  });
</script>
